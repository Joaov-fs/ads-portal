## Verificação obrigatória do GitHub

Antes de usar os arquivos locais em qualquer tarefa, execute `git fetch origin`
e compare a revisão local com a branch de produção no GitHub
(`Joaov-fs/ads-portal`, atualmente `main`). Se houver commits novos e a árvore
estiver limpa, atualize com `git merge --ff-only origin/main`. Preserve mudanças
locais e não use uma cópia desatualizada como base para publicação. Se não for
possível verificar o remoto, informe o impedimento antes de prosseguir com trabalho
que dependa da versão atual.

## Rotina editorial autorizada

O usuário autorizou publicação sem aprovação editorial prévia, todos os dias às
08h, 15h e 19h, no fuso `America/Sao_Paulo`. A rotina está agendada nesta conversa
do Codex, sob o nome "PortalFina: notícias às 8h, 15h e 19h".

Siga `docs/formato-de-noticias.md`, verifique fontes oficiais atuais e evite
duplicações. Preserve o padrão de ilustrações próprias de
`scripts/covers/scenes.py`, com capa e detalhe inspecionados visualmente. Execute
as validações exigidas antes de publicar pelo fluxo GitHub/Vercel e confirme a
matéria e as imagens na URL pública antes de anunciar sucesso.

Após cada publicação confirmada, entregue nesta conversa três blocos de código
separados, identificados como WhatsApp, Instagram e Facebook, com texto chamativo
e fiel e o link completo da notícia. Os textos são para o usuário compartilhar;
a autorização não inclui postar diretamente nas redes sociais. Informe falhas
reais de execução sem apresentar a publicação como concluída.
